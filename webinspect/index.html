The Report

Eight sections, one click

Every finding shows the evidence behind it, so you can disagree with WebInspect when WebInspect is wrong.

Overview

URL, title, language, encoding, HTTPS, canonical, robots and viewport, with counts for words, images, links, scripts, styles, requests and transferred bytes.

Technology

Frameworks, CMS, ecommerce platforms, CSS frameworks, JavaScript libraries, analytics, payment providers, infrastructure and fonts. Each rated detected, likely or possible rather than asserted as fact.

SEO

Title, meta description, heading outline, canonical, robots, Open Graph and Twitter tags with a card preview, structured data types and URL shape.

Accessibility

Alt text, form labels, link and button names, page language, landmarks, duplicate ids, ARIA references, roles, tabindex, iframe titles, video captions, focus indicators and colour contrast against WCAG AA.

Performance

Resource counts and sizes by type, the largest and slowest resources, render-blocking scripts, cache hits, first paint and DOM ready.

Mobile

Viewport declaration, zoom locks, horizontal overflow, fixed pixel widths, touch target sizes and small text.

Security configuration

HTTPS, mixed content, Subresource Integrity, form submission targets, iframe sandboxing and insecure links.

Content and links

Words, paragraphs, reading time, link classification, and where the external links actually go.

And what you can do with it

Highlight any finding directly on the page, export the whole report as JSON or CSV, copy a plain summary, and optionally check whether the page's links still resolve.

How It Works

Four steps, no setup

1

Open any page

The site you are building, auditing, or just curious about.

2

Ask for a report

Click the toolbar button, right-click the page, or press Ctrl Shift U.

3

Read the score

An overall score, a breakdown by category, and every issue with its evidence.

4

Act on it

Highlight a finding on the page, or export the report as JSON or CSV.

Chrome reserves Ctrl Shift I for DevTools, so that one is not available to extensions. The shortcut can be changed at chrome://extensions/shortcuts.

Built To Be Honest

A check that could not run is not a failure

Most audit tools round everything down to a number. WebInspect tells you which parts it could not measure, and takes them out of the score rather than counting them against you.

Five outcomes, not two

A page Chrome will not let it read has not failed anything.

  • Passed
  • Issue
  • Not found
  • Could not check
  • Not applicable

Nothing to measure scores nothing

A category with nothing to measure scores null rather than zero, and its weight is shared across the rest. Colour contrast returns no ratio rather than a wrong one.

No compliance claims

Accessibility results are described as "automated checks found", never as compliance. Automated testing catches missing alt text, unlabelled fields and insufficient contrast. It cannot tell you whether a page works with a screen reader.

Evidence, always

Every finding carries the selector and the markup behind it, and can be highlighted on the page. Detection is rated detected, likely or possible rather than asserted.

Privacy

There is nowhere to upload anything to

WebInspect has no servers, no account and no telemetry. Nobody at Elevven11 Studio can see what you browse, what you inspect, or what WebInspect finds.

Not on the page until you ask

There is no content script in the manifest, so nothing of WebInspect exists on a page until you ask for a report on that page.

522 sites it will not read

Large platforms, where a report is not actionable, and pages that routinely hold personal information: AI chats, webmail, cloud storage, banking, health and government. The check runs before the page reader is injected, so a skipped page is never read.

Counted, never stored

Page text is counted and the number leaves the page; the words do not. Form structure is read, form values never are. No browsing history is kept.

No permissions at install

Host permissions are asked for only if you turn on automatic inspection or link checking, and can be withdrawn from the settings page at any time.

One network feature, off by default

The link checker is the only thing that touches the network, it needs a permission you grant explicitly, and it only runs when you press "Check links". Nothing else makes a request.

Yours to delete

Everything WebInspect holds is one store on your device. "Reset WebInspect" in settings empties it. There is nothing held anywhere else.

FAQ

Common questions

What does it cost?

Nothing, and it stays that way. WebInspect carries one house advertisement for the studio's own work at the foot of the popup, labelled "Ad", served from a list that ships inside the extension. Opening the popup makes no request and tells nobody it was opened. One click turns it off permanently.

Which browsers does it work in?

Chrome 116 and later, and the Chromium browsers that install Chrome extensions, such as Edge, Brave and Opera. It is a Manifest V3 extension.

Is this a replacement for DevTools or Lighthouse?

No. It answers a different question. Lighthouse runs a page in a controlled environment and scores it; WebInspect reads the page in front of you and tells you what it is made of and what is wrong with it, in the time it takes to open a popup. They are useful together.

Why will it not inspect the page I am on?

It is probably on the skip list: a large platform, or a kind of page that routinely holds personal information. The popup says which site it is and why, and offers both ways out: inspect it once, or turn the skipping off in settings. Platforms where users control their own markup are never skipped, so GitHub Pages, Vercel, Netlify, Shopify, Substack and WordPress.com sites stay inspectable.

Can I trust the accessibility score?

Trust it for what it measures. Automated checks reliably catch missing alt text, unlabelled fields and insufficient contrast. They cannot tell you whether a page is usable with a screen reader, and WebInspect says so rather than implying a clean run means compliance.

Does it work on a page behind a login?

Yes, on any page Chrome lets an extension read, and the report never leaves your device. Sites that routinely hold personal information are on the skip list, so a webmail or banking page is not read unless you explicitly ask for it once.
