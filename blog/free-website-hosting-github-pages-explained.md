# How Does Free Website Hosting on GitHub Pages Work?

Why a simple business website can be hosted for free on GitHub Pages, what makes a site eligible, and when you would need paid hosting.

Most people assume a website comes with a hosting bill every month. For many small business sites, that bill is optional. This guide explains how free hosting on GitHub Pages works, which sites qualify, and where the limits are.

## What hosting actually is

A website is a set of files: pages, images, styles and a few scripts. Hosting is a computer that stores those files and sends them to anyone who types your address or taps your link. If the host goes offline, so does your site.

Traditional hosting companies rent you space on their servers. You pay monthly or yearly for as long as the site is live. That fee covers the server, and often features a simple site never uses, like databases and email accounts.

## What GitHub Pages is

GitHub is a service developers use to store and manage code. GitHub Pages is a feature of it that takes a folder of website files and publishes them on the internet. For public sites it is free, and it serves pages over HTTPS, so visitors see the padlock in their browser.

Every GitHub Pages site gets a free default address. You can keep that address, or connect your own domain like `www.yourbusiness.com.ng`. More on that below.

## What "eligible static site" means

GitHub Pages only hosts **static** sites. A static site is made of files that look the same for every visitor. The server does not build anything on the fly. It just hands over the files.

That covers most small business websites:

- A home page with your services and prices
- An about page and contact details
- A WhatsApp button and social media links
- A photo gallery or menu
- A product catalogue where the order is sent to your WhatsApp

What it does not cover is anything that needs a server to think or remember. If a site needs any of the following, it is not static:

- Customer accounts and logins
- A database that stores orders, bookings or user data
- Online payments processed on the site itself
- Private APIs or other server-side processing

Those sites need a different kind of hosting, and that hosting usually does cost money.

## The limits to know about

Free does not mean unlimited. GitHub publishes usage limits for Pages, covering things like total site size and monthly traffic. A typical business site with a few pages and compressed photos sits far below them.

The practical limits are more about what you can build:

1. **No server code.** Contact forms need a third-party form service, because the site cannot process submissions itself.
2. **Changes go through files.** There is no admin dashboard where you log in and edit text. Someone edits the files and publishes them again.
3. **Large media belongs elsewhere.** Long videos are better hosted on YouTube and embedded, so the site stays fast.

If you understand these up front, free hosting is a sound choice rather than a shortcut.

## Questions to ask any web designer about hosting

Whoever builds your site, ask these before you pay:

1. Does my site need a server, or can it be static?
2. If there is a hosting fee, what exactly does it pay for?
3. Who owns the account the site is hosted on?
4. If I stop working with you, can the site be moved?

A good answer to the first question can save you a recurring bill for years. If your site is mostly information and contact details, it can almost certainly be static.
